Setup dari awal

Enam langkah. Satu desktop siap dipakai.

Ikuti urutannya. Kalau panel menunjukkan secret belum lengkap, selesaikan dulu sebelum menekan tombol NYALAKAN.

01

Masuk dengan akun GitHub-mu

Tekan Masuk dengan GitHub pada dashboard lalu setujui akses aplikasi. Login ini menghubungkan dashboard ke repo milik akunmu.

  • Pastikan kamu login ke akun yang benar.
  • Token OAuth dipakai untuk mengelola repo milikmu; dashboard tidak bisa melihat nilai secret RDP/Tailscale.
  • Kalau GitHub meminta izin repo, baca layar persetujuan sebelum menyetujui.
Yang akan terjadi: setelah login, halaman menampilkan panel Repo kamu dan tombol untuk membuat repo dari template.
02

Buat repo kerja milikmu

Di panel Repo kamu, pilih nama repo, tentukan publik atau privat, lalu tekan BUAT REPO DARI TEMPLATE.

  • Repo baru dibuat di akunmu, misalnya username/XyRDP.
  • Pilih publik/privat sesuai kebutuhan dan pahami batas kuota GitHub Actions akunmu.
  • Jika nama repo sudah dipakai, ganti dengan nama lain lalu ulangi.
Periksa: status repo berubah menjadi “perlu secret” atau “siap”. Workflow untuk sesi hanya berjalan pada repo milikmu.
03

Tambahkan dua secret wajib

Tekan BUKA SECRETS. Di repo GitHub-mu, buka Settings → Secrets and variables → Actions, lalu buat repository secret berikut.

RDP_PASSWORD
TAILSCALE_AUTH_KEY
  • RDP_PASSWORD: buat sandi unik minimal 16 karakter ASCII, campuran huruf besar/kecil, angka, dan simbol sederhana. Contoh format saja (jangan dipakai persis): v7M!4qR-9Tz2-Lp6K8x. Buat nilai acak sendiri, simpan di password manager, dan hindari spasi di awal/akhir atau karakter yang sulit diketik dari HP. Jangan gunakan ulang sandi email/GitHub.
  • TAILSCALE_AUTH_KEY: buat di Tailscale Admin → Settings → Keys. Pilih reusable; aktifkan ephemeral bila tersedia supaya node sesi dibersihkan otomatis.
  • Opsional: NGROK_AUTHTOKEN untuk tunnel ngrok; CLEANUP_TOKEN untuk pembersihan run lama.
Privasi & penerapan: nilai secret hanya diisi langsung di GitHub. Dashboard membaca nama secret untuk mengecek kelengkapan, bukan nilainya. RDP_PASSWORD khusus untuk login desktop dan berbeda dari sandi admin dashboard. Username awal xyadmin dapat diganti lalu disimpan sebagai default lewat panel Tampilan di dashboard (3–20 karakter ASCII; huruf/angka di awal, lalu huruf, angka, _ atau -). Jika secret sandi diubah, sesi baru diperlukan.
Tools: Git, Node.js, Python, 7-Zip, Visual Studio 2022, .NET, Java, CMake, GCC/GDB sudah ada di image runner. VS Code dan Notepad++ tersedia sebagai pilihan install opsional di dashboard.
04

Periksa lalu nyalakan sesi

Kembali ke dashboard, tekan PERIKSA / RAPIKKAN LAGI, lalu tunggu sampai status repo menjadi siap.

  • Pilih durasi. Batas maksimum job GitHub-hosted pada workflow ini adalah 6 jam.
  • Untuk pemakaian HP, jalur Tailscale direkomendasikan. Grafis Mesa adalah render software berbasis CPU—bukan GPU fisik.
  • Tema gelap, transparansi taskbar, dan profil ringan aktif secara default; pilihan VS Code/Notepad++ tetap opsional.
  • Tekan NYALAKAN satu kali. Siapkan beberapa menit untuk setup awal; editor yang dipilih menambah waktu unduh/pasang.
Jangan panik jika masih “menyiapkan”. Tunggu hingga status AKTIF dan alamat Tailscale terlihat. Jangan pakai IP dari sesi sebelumnya. Angka RAM di dashboard adalah snapshot akhir setup, bukan pemantauan live.
05

Sambungkan dari HP dengan XyDesk Remote

Pasang aplikasi Tailscale di HP dan login ke akun Tailscale yang membuat auth key. Setelah itu buka aplikasi XyDesk Remote.

  • Pilih Koneksi RDP Penuh.
  • Isi Host dengan IP 100.x terbaru dari panel Koneksi, Port 3389, user yang tampil di panel Koneksi (default xyadmin).
  • Masukkan nilai RDP_PASSWORD yang kamu simpan di secret GitHub.
  • Jika aplikasi meminta konfirmasi sertifikat RDP sesi sekali-pakai, cocokkan konteksnya lalu terima.
Tips: kalau gagal, pastikan Tailscale aktif di HP, login akun yang sama, status dashboard AKTIF, dan IP diambil dari sesi terbaru. Cek username yang tampil di panel Koneksi dan nilai RDP_PASSWORD dari repo yang sama; pastikan tidak ada spasi tambahan. Perubahan username atau secret sandi hanya berlaku setelah sesi baru.
06

Simpan pekerjaanmu dan matikan sesi

Runner adalah VM sementara. Salin file penting ke penyimpananmu sendiri sebelum sesi habis.

  • Gunakan tombol MATIKAN jika sudah selesai—jangan biarkan sesi berjalan tanpa perlu.
  • Kalau durasi habis, sesi akan berhenti otomatis dan VM dibuang.
  • Untuk sesi baru, jalankan workflow lagi; alamat koneksi baru akan dibuat.
Ingat: desktop ini bukan cloud storage. File di disk runner dapat hilang saat sesi berakhir.

LANGKAH 1/5 · akun GitHub
Baca sebelum memakai

Jelas dari awal, tanpa janji berlebihan.

Beberapa batasan layanan penting supaya kamu tahu apa yang sebenarnya berjalan.

SISTEM

Windows 10-style, bukan Windows 10 asli

Runner GitHub yang dipakai adalah Windows Server 2022 dengan tampilan/tweak menyerupai Windows 10. Bukan edisi Windows 10 desktop berlisensi.

DURASI

VM sementara, maksimal 6 jam

Sesi akan berhenti otomatis. Data lokal di runner bisa hilang—simpan pekerjaan di repo, cloud drive, atau media milikmu sendiri.

GRAFIS

Render software, bukan GPU fisik

OpenGL/Vulkan tersedia lewat llvmpipe/lavapipe berbasis CPU. Aplikasi 2D atau sebagian game ringan mungkin berjalan; game 3D tidak dijamin. RAM runner ditetapkan GitHub, jadi profil ringan hanya mengurangi sebagian beban latar.

AKSES

Gunakan jalur yang disarankan

Tailscale + XyDesk Remote adalah jalur HP yang direkomendasikan. Jangan membagikan auth key, sandi, atau alamat sesi aktif kepada orang lain.

KUOTA

Ikuti aturan GitHub dan Tailscale

Biaya, kuota menit, batas penggunaan, dan kelayakan akun mengikuti kebijakan terbaru masing-masing platform. Periksa sebelum menjalankan sesi lama/berulang.

KEAMANAN

Jangan simpan data sangat sensitif

Gunakan sandi unik sekali pakai dan jangan isi rahasia kerja, data finansial, atau file sensitif pada VM sementara.
