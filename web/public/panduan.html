Kenapa akun bisa disuspend?

Ketentuan GitHub Actions yang berlaku sejak 27 Agustus 2026 membatasi GitHub-hosted runners untuk mengembangkan, menguji, men-deploy, atau menerbitkan software yang terkait dengan repo. Ketentuannya juga memperingatkan bahwa penggunaan di luar batas itu bisa menyebabkan job dihentikan, Actions dibatasi, repo dinonaktifkan, atau akun disuspend.

XyRDP menahan Windows runner sampai enam jam dan menyediakan desktop RDP untuk penggunaan umum. Pola ini berisiko dianggap penggunaan Actions sebagai layanan remote desktop, bukan CI/test proyek. Pemeriksaan pemilik repo, repo privat, Tailscale, atau secret yang valid tidak mengubah tujuan penggunaan tersebut.

Notifikasi GitHub adalah sumber yang menentukan alasan spesifik tiap akun. Jika suspend terjadi karena alasan lain, hanya pemilik akun dan GitHub Support yang dapat memastikan.

Langkah aman sekarang

  1. Jangan tekan start atau dispatch workflow. Tombol dashboard/API diblokir. Job baru dari workflow utama dilewati sebelum runner dibuat.
  2. Jangan buat akun/repo lain untuk menghindari suspend. Itu dapat memperburuk peninjauan.
  3. Untuk salinan template lama, buka Actions, pilih workflow XyRDP, buka menu …, lalu pilih Disable workflow. Salinan template lama tidak diperbarui otomatis.
  4. Jika tidak lagi menggunakan jaringan sesi, buka Tailscale Admin → Settings → Keys dan revoke auth key yang terkait. Jika ada node non-ephemeral, hapus node yang tidak dikenal di Machines.
  5. Di GitHub repo lama, buka Settings → Secrets and variables → Actions. Hapus secret yang tak lagi digunakan; GitHub tidak menampilkan kembali nilai secret yang tersimpan.

  3. Tunggu jawaban di tiket yang sama. Jangan membuka banyak tiket atau membuat akun baru untuk melewati pembatasan.

Login tiap refresh & kenapa dashboard bisa suspend (vs fork manual aman)

Login tiap refresh (sudah diperbaiki): sesi dashboard disimpan di cookie ghs (GitHub) & sid (admin) terenkripsi AES-256-GCM + SESSION_SECRET + Max-Age. Bug lama: fetch tanpa credentials:'include' bikin cookie tidak terkirim → /api/auth/status balikin tanpa mode → frontend paksa showLogin() tiap reload. Fix sekarang: fetch(...,{credentials:'include'}), SESSION_TTL_DAYS 7→30 hari, ADMIN_TTL 12 jam→30 hari, plus cache localStorage: xyrdp_me_cache biar refresh tetap masuk app dulu sambil verifikasi background. Pastikan SESSION_SECRET di Vercel tidak ganti-ganti (kalau diganti semua cookie lama invalid).

Kenapa “Masuk dengan GitHub” via dashboard lebih berisiko suspend daripada fork manual?

  • Fork manual (klik “Use this template” / Fork di github.com): aksi native GitHub, rate limit per akun kamu, repo hasil fork jadi kamu/RdpFree dan run workflow jalan di repo kamu pakai token kamu sendiri. Tidak melewati IP Vercel/dashboard. Paling aman.
  • Dashboard “Masuk dengan GitHub” (OAuth App): setelah OAuth, dashboard pakai token kamu untuk POST /repos/{owner}/{repo}/generate (buat repo dari template), PUT /actions/secrets, dan POST /actions/workflows/.../dispatches — semua lewat API dari IP Vercel (xyrdp-dash.vercel.app). Kalau banyak user klik “Buat Repo” + “Start” berulang dalam menit yang sama, GitHub bisa deteksi sebagai abuse/automation spam (repo generate + workflow_dispatch spam dari satu IP/OAuth app) → flag → suspend.
Dashboard sekarang dibatasi: max 2× Start per 5 menit per user/IP + blokir dispatch kalau masih ada run queued/in_progress (harus Stop dulu). Buat hindari deteksi spam GitHub.

Cara aman pakai dashboard (supaya tidak suspend):

  1. Paling aman: fork manual dulu di github.com → buka xykal/XyRDP → Use this template → Create a new repository (beri nama RdpFree) → baru login dashboard (otomatis pakai kamu/RdpFree).
  2. Jangan spam “Buat Repo” atau “Start” — tunggu run selesai. Kalau buat repo baru, diamkan 1–2 menit sebelum start.
  3. Isi secret RDP_PASSWORD & TAILSCALE_AUTH_KEY (jangan share tskey-auth-... publik). Optional: GTA_SA_URL untuk SAMP, NGROK_AUTHTOKEN jika pakai ngrok.
  4. Jangan pakai 1 akun untuk buat 5+ repo RDP dalam sejam — itu pola spam yang paling sering ke-flag.
  5. Login dashboard sekarang tahan 30 hari — tidak perlu login tiap refresh. Kalau tetap disuruh login: clear cookie ghs/sid → login ulang, atau cek Vercel SESSION_SECRET (≥32 char, jangan di-rotate). Logout → hapus cache localStorage.

Catatan: kebijakan GitHub 27 Aug 2026 tetap berlaku — runner GitHub bukan untuk RDP umum 6 jam. Panduan ini hanya mengurangi risiko automation spam, bukan mengubah batas Terms.

Status teknis wallpaper

Kami menemukan bahwa skrip lama menganggap wallpaper berhasil tanpa memeriksa hasil fungsi Windows dan menulis pengaturan ke profil runner/default, bukan selalu ke sesi RDP yang sedang dilihat pengguna. Karena sesi baru dijeda, perubahan wallpaper tidak akan diterapkan atau diuji sekarang. Status “berhasil” pada log lama belum membuktikan gambar tampil di desktop. Perbaikan perlu diuji pada host desktop yang memang mengizinkan akses RDP.

Butuh remote desktop?

Gunakan layanan Windows/remote desktop yang secara eksplisit mengizinkan akses interaktif sesuai paket dan kebijakannya. Setelah host yang sesuai dipilih, panduan bisa dibuat ulang dari awal—termasuk Tailscale HP, akses admin Tailscale, pengelolaan key, GitHub secrets bila memang masih dibutuhkan, dan diagnosis wallpaper.

Dashboard saat ini hanya untuk memantau repo/run lama dan mengelola secret. Fitur set-secret otomatis dari dashboard sengaja tidak tersedia selama jeda.
